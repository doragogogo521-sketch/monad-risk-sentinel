# Monad Risk Sentinel MVP 产品文档

## 产品定位

Monad Risk Sentinel 是一个面向 Monad DeFi 生态的事件驱动风险情报基础设施。产品不把自己定位为新闻聚合器、交易终端或自动管理资金的投资机器人，而是解决一个更具体的问题：当外部地缘金融事件影响银行、托管方、发行机构、稳定币储备或跨境结算时，Monad 上的借贷协议、Vault 和流动性池如何及时知道自己暴露了什么风险，以及是否需要调整已有的风控规则。MVP 以稳定币为第一类资产，以借贷协议为第一类集成对象，把“地缘事件—金融机构—稳定币—Monad 协议敞口—风控动作”做成一条可解释、可验证、可演示的完整链路；长期可以扩展到 RWA、质押衍生品、跨链桥和 DAO Treasury，但第一版不试图覆盖整个 DeFi，也不承诺预测战争、市场价格或资产收益。

## 用户问题与核心假设

稳定币和 DeFi 协议已经能够监测价格、流动性、交易量、抵押率、清算和智能合约权限，但这些链上指标往往在风险已经发生后才明显。发行方的储备托管关系、银行或清算通道受到制裁、某地区资本管制升级、发行机构暂停赎回等事件，可能先在现实世界发生，再通过赎回、做市、跨境结算和流动性行为传导到链上。现有协议通常需要风险团队人工阅读公告、监测社交媒体、判断资产关联，再通过治理或风险管理员调整 LTV、借款上限、交易费或仓位限制。MVP 的核心假设是：协议不一定需要一个新的交易产品，但可能需要一个把外部事件结构化、解释其资产暴露并提供机器可读信号的风险层；如果一个外部事件无法映射到具体发行方、托管方、稳定币、链上池子或协议动作，就不应被当作可执行的 DeFi 风险信号。

## MVP 场景

MVP 只实现一条“稳定币地缘金融风险传导”路径：某现实世界事件提高某金融机构、托管方或发行方的风险，Agent 根据公开证据建立事件与稳定币的关联，再读取 Monad 上的稳定币价格、流动性、持仓和协议敞口，形成风险状态；示例借贷协议读取该状态后，按照预先写入合约的策略把该稳定币的 LTV 从 75% 调低至 45%，停止新增借款但允许还款和退出。第一版不要求真实第三方协议接入，使用一个自己部署的最小借贷示例合约作为 reference integration，但界面和接口必须按照未来第三方协议可接入的方式设计，避免演示沦为“自己写的注册表读取自己写的合约”。Demo 至少展示一个外部事件、一条完整传导路径、一个 Monad 链上状态更新和一个协议参数变化；如果无法完成真实外部数据接入，则使用固定但可追溯的事件输入，并明确标注为 replay / simulation，不伪装成实时预测。

## 地缘风险信号体系

产品不把“战争新闻”直接转换为 RED 风险，而是将学术和研究型指标作为外部风险因子，再经过机构关联和链上验证。第一类因子是宏观地缘政治风险，可参考 Caldara 与 Iacoviello 的 Geopolitical Risk Index；该指数基于新闻报道衡量不利地缘政治事件及其风险，但它是宏观背景因子，不能单独触发某个稳定币的合约动作。[GPR 研究论文](https://www.matteoiacoviello.com/gpr_files/GPR_PAPER.pdf) 第二类因子是冲突事件强度与地理位置，可参考 UCDP Georeferenced Event Dataset 和 ACLED 的结构化事件数据，用事件数量、伤亡、参与者、地理距离和升级速度描述地区风险；这些数据应作为验证或历史回放来源，而不是被包装成没有延迟和误差的实时真相。[UCDP 数据集](https://ucdp.uu.se/downloads/)、[ACLED 方法](https://acleddata.com/press-office-faqs) 第三类因子是更接近 DeFi 传导的制度事件，包括制裁、监管公告、银行或托管机构状态变化、资本管制、发行方赎回暂停和官方风险披露。MVP 优先使用第三类因子，并用前两类因子提供背景分数，因为制度事件更容易关联到具体实体和协议动作。

## 产品逻辑

系统首先对外部事件进行标准化，生成事件类型、受影响地区、相关机构、时间、来源、可信度和有效期；事件类型不采用开放式新闻标签，而采用有限枚举，例如 SANCTIONS、BANKING_RESTRICTION、CUSTODIAN_RISK、REDEMPTION_PAUSED、CAPITAL_CONTROL 和 CONFLICT_ESCALATION。随后建立 Entity Graph，把地区、政府机构、银行、托管方、发行方、稳定币、预言机、流动性池和借贷市场连接起来，并为每条关联保存来源和置信度。只有当事件能够通过图谱关联到一个具体稳定币或其关键服务方时，系统才生成资产级风险；如果只是一个宏观风险上升但没有资产关联，系统只产生 WATCH 级背景提醒。

风险计算拆成两个分数。Geopolitical Shock Score 衡量外部事件本身的强度，考虑事件严重程度、来源可信度、事件新颖性、升级速度、地理重要性和数据一致性；On-chain Exposure Score 衡量某个稳定币或协议暴露在该事件下的程度，考虑发行方和托管方关联、稳定币赎回依赖、Monad 流动性、借贷池持仓比例、持仓集中度和最近流动性变化。最终的 Transmission Risk 不是简单的新闻情绪分，而是 `Geopolitical Shock Score × On-chain Exposure Score`，并由新鲜度、证据数量和冲突来源惩罚项校正。风险等级采用 WATCH、YELLOW、ORANGE、RED 四档：WATCH 只提示可能相关；YELLOW 要求进一步验证；ORANGE 可以触发协议降低 LTV、限制新增借款或停止 Vault 新增仓位；RED 只能在官方事件、链上异常或多方证明达到阈值后触发暂停或紧急流程。

## 数据与 Agent 架构

MVP 的数据层由三类输入组成：外部证据、实体关系和 Monad 链上状态。外部证据可以是官方监管公告、发行方公告、托管方披露、结构化冲突事件数据和经筛选的新闻；实体关系由人工配置和 Agent 辅助抽取共同建立，不能让模型凭一段新闻自动断言“某稳定币储备一定在某银行”；链上状态由 Monad RPC、事件日志和定时读取组成，包括稳定币价格、DEX 池流动性、交易量、持仓、管理员变更、pause/freeze/blacklist 事件、预言机更新时间和借贷池抵押敞口。Risk Intelligence Agent 的职责是抽取事件、关联实体、生成传导解释和提交风险断言，不拥有直接冻结资金的权限；所有高影响动作由链上策略合约、协议治理、多签或受限风险角色执行。

## Monad 原生机制

Monad 的作用不是保存一篇风险报告，而是提供一个可被 DeFi 合约直接读取的、带有效期和证据指纹的风险状态层。核心合约 `MonadRiskRegistry` 为每个资产保存 `riskLevel`、`geopoliticalScore`、`exposureScore`、`reasonCode`、`updatedAt`、`validUntil`、`evidenceHash` 和 `attestor`，并暴露 `getRiskState(asset)`、`isActionAllowed(asset, action)` 和 `submitAttestation(...)` 接口。风险状态必须有 TTL，过期后自动降级为 UNKNOWN，防止旧事件永久影响协议；风险状态更新必须受到角色、阈值和变更幅度约束，Agent 不能任意修改协议的 LTV。reference lending pool 预先定义状态与动作映射：GREEN 允许正常借贷，YELLOW 降低 LTV，ORANGE 禁止新增借款但允许还款，RED 暂停新增抵押与借贷。这样风险信号在链上承担的是状态发布、权限控制和策略执行，而不是单纯存证。

## 证据、挑战与错误信号处理

MVP 不建立复杂的去中心化预言机网络，但必须承认现实事件存在错误、延迟和争议。每一条风险断言都保存证据哈希、来源类型、创建时间、有效期和提交者；低可信度来源只能产生 WATCH 或 YELLOW；影响资金规则的 ORANGE / RED 状态需要官方来源、链上证据或第二个独立证明。后续版本可以加入风险断言质押与挑战机制：提交者为断言质押 MON，挑战者提交反证，经过预设窗口和仲裁后，错误断言被罚没，正确挑战获得奖励。MVP 可以先把 challenge 设计成只读模拟或治理按钮，但要在产品逻辑中说明它如何解决“谁为错误信号负责”的问题。与其让 AI 直接拥有紧急权限，不如让 AI 只能产生可审计的建议，让协议方选择是否启用自动策略。

## 用户与协议接入方式

第一类用户是 Monad 借贷协议、Vault 和稳定币应用的风险管理者；他们不需要替换原有价格预言机，而是增加一个外部风险覆盖层。接入方可以通过 Solidity 接口在借款、存款、铸造或策略执行前读取风险状态，也可以通过事件订阅、SDK 或 API 获取解释和证据。产品输出不应只有“风险 78 分”，而应包括受影响资产、传导路径、触发条件、建议动作、证据、更新时间和有效期，例如“Custodian B sanctions risk → Stablecoin C redemption exposure → Lending Pool D holds 28% of collateral → recommended action: reduce LTV to 45%”。协议最终决定是否采用建议，产品不承诺协议一定安全，也不替协议承担治理、清算或投资责任。

## 前端与 Demo

前端首页展示一个 Monad 风险地图和传导路径，而不是新闻列表。用户先看到稳定币列表、风险状态和 Monad 上的协议敞口，再点击某资产查看“外部事件—机构—稳定币—协议”的关系图、证据来源、风险分数组成和链上交易。Demo 采用一个固定事件回放：输入某托管或发行机构相关的制度风险事件，Agent 输出结构化断言；系统读取稳定币的模拟价格和流动性变化；`MonadRiskRegistry` 更新为 ORANGE；reference lending pool 读取状态并将 LTV 从 75% 改为 45%；前端展示更新前后的参数、交易哈希、事件证据和允许 / 禁止的用户动作。整个流程必须在演示中可重复，不能依赖不可控的实时新闻接口。

## 非目标与边界

MVP 不做全球地缘政治预测，不做自动交易，不做投资组合管理，不发行稳定币或 RWA，不保证收益或资产安全，不声称 AI 可以判断战争结果，也不把宏观新闻直接作为清算依据。MVP 不需要覆盖所有稳定币，只选择一个具有清晰发行方、储备或赎回逻辑、并能在 Monad 上构造链上敞口的代表性资产；不需要接入真实第三方协议，但 reference integration 必须使用公开接口设计。所有现实世界关系都要标注为证据支持的关联、待验证关联或假设，避免产品把推测包装成事实。

## 成功标准与评审叙事

MVP 的技术成功标准是：能够完成一次结构化外部事件输入、实体关联、稳定币暴露计算、风险断言提交、Monad Registry 状态更新和借贷策略改变；所有关键状态都有可追踪的来源、时间戳和交易哈希。产品成功标准不是预测价格，而是证明一个协议可以因为“现实世界事件造成的传导风险”而改变自己的链上行为。评审叙事应当是：传统预言机回答“资产现在值多少钱”，链上分析回答“刚刚发生了什么”，Monad Risk Sentinel 回答“外部机构与地缘金融事件如何通过稳定币进入协议风险，以及协议可以按什么规则响应”。短期产品是稳定币风险传导的 Monad-native 基础设施，长期才扩展为跨资产、跨协议的外部风险智能网络。

## 一天内的开发优先级

第一优先级是完成 `MonadRiskRegistry`、风险等级枚举、TTL、证据哈希和 `getRiskState` 接口；第二优先级是完成一个 reference lending pool，使 LTV 能根据风险状态从 75% 切换到 45%；第三优先级是做一个固定事件 replay 脚本，生成稳定币风险断言并调用 Registry；第四优先级是做前端传导路径和参数变化展示；最后再补充 Agent 的自然语言解释、历史数据和挑战机制。如果时间不足，宁可保留一个可信的事件回放和完整链上闭环，也不要新增多个资产、多个协议或复杂的实时新闻抓取。
