# Monad Risk Sentinel 联调基准 v1

依据：`产品文档原件.md`。本文件将其冲突处收敛为当前前端采用的统一约定；不代表合约同学已确认或部署。

## 风险枚举与策略

GREEN 是正常状态；WATCH 是有背景事件但无充分资产级关联的提醒；UNKNOWN 是无有效断言、TTL 到期或断言无效。UNKNOWN 不是 GREEN，也不是风险严重程度的最低档。

| 编码（拟定 uint8） | 状态 | LTV bps | 新增借款 | 新增抵押 | 还款 | 提取抵押 |
|---|---|---:|---|---|---|---|
| 0 | UNKNOWN | min(上次采用值,4500) | 禁止 | 禁止 | 允许 | 满足抵押约束 |
| 1 | GREEN | 7500 | 额度内允许 | 允许 | 允许 | 满足抵押约束 |
| 2 | WATCH | 7500 | 额度内允许 | 允许 | 允许 | 满足抵押约束 |
| 3 | YELLOW | 6000 | 额度内允许 | 允许 | 允许 | 满足抵押约束 |
| 4 | ORANGE | 4500 | 禁止 | 允许 | 允许 | 满足抵押约束 |
| 5 | RED | 4500 | 禁止 | 禁止 | 允许 | 满足抵押约束 |

YELLOW=60%、UNKNOWN 保守限制、数值编码是为解决原文歧义而新增的 MVP 约定，不是原文给出的完整参数。合约如采用不同编码须先统一或写显式适配，禁止直接按名字排序推断。禁止用枚举数值大小判断 UNKNOWN 是否安全。

无历史参数时 UNKNOWN LTV 默认 45%。提取约束为 `debtValue <= remainingCollateralValue × activeLtv`；还款受实际债务、钱包余额、代币授权约束。降低 LTV 不在本原型触发强制清算；页面显示超额债务时提示先还款或补充抵押。真实合约应另外定义清算规则与预言机异常策略。

## 统一单位

- `updatedAt` / `validUntil` / `occurredAt`：Unix 秒。`now >= validUntil` 即失效；未来 updatedAt 不接受。
- LTV、置信度、敞口：bps，10000=100%。
- geopoliticalScore / exposureScore / transmissionScore：0–100。示例 80×75/100×0.95=57；分数未经校准，不是损失概率。
- 前端模拟金额使用整数分（两位小数），容量计算向下取整。真实 ERC-20 decimals 以各代币接口为准，不能直接套用两位小数。
- riskLevel 字符串 + riskLevelCode 数值在报告中并存；链上编码需与此表确认。
- evidenceHash：前端 SHA-256(JSON.stringify(完整报告))，报告不包含自身哈希。拟定链上 bytes32；若合约或 Agent 用 keccak256 或规范化 JSON，三方必须先统一算法与字节内容。

## Agent 数据约定

报告结构见 `../frontend/report.schema.json`。前端当前用固定样例生成报告，未调用 AI、RPC 或任何第三方研究服务。

必需包含：simulation、asset、event（有限 eventType、entity、region、occurredAt、sourceType、confidenceBps）、relations（evidenceId 与关联状态）、evidence、market、risk、suggestedPolicy、limitations。

事件类型范围：SANCTIONS / BANKING_RESTRICTION / CUSTODIAN_RISK / REDEMPTION_PAUSED / CAPITAL_CONTROL / CONFLICT_ESCALATION。关系状态：EVIDENCED / UNVERIFIED / HYPOTHESIS / SIMULATION。

无明确资产关联只输出 WATCH。低可信度证据最高 YELLOW。ORANGE / RED 需官方类型证据、可验证链上证据或独立第二证明达到门槛；RED 还应有更严格验证。当前模拟不能满足真实生产证据资格，必须保留 simulation 标记。分类门槛、来源去重和校正项由 Agent/合约负责人最终确定，前端不做自动评分升级。

## 合约接口对接清单

以下为目标语义，不是已有 ABI，也不声称合约已实现：

- Registry：`getRiskState(asset)` 返回原始断言及时间戳，消费者根据 TTL 判断有效级别；`isActionAllowed(asset, action)`；`submitAttestation(...)`。
- Action 拟定编码：DEPOSIT_COLLATERAL=0、BORROW=1、REPAY=2、WITHDRAW_COLLATERAL=3。必须和合约确认；返回允许也不替代钱包/债务/抵押等检查。
- Lending：读取仓位、当前 LTV、借款权限；borrow、repay、depositCollateral、withdrawCollateral 函数签名与 approve 流程。
- 提供 Registry、Pool、mUSD、dUSD 地址，测试网 chain ID、RPC、区块浏览器、ABI、decimals、授权角色和策略版本。
- UI 对 Registry 更新和 Pool 策略应用分别展示交易回执：若 Pool 动态读取 Registry，可展示读取结果并标明只有一笔更新交易。禁止捏造第二笔交易。
- 未收到真实回执前交易哈希为空或“待接入”。密钥不得放入前端。

## 固定演示脚本

1. 有效 GREEN 基线：mUSD=$1，抵押 1000 mUSD，债务 200 dUSD，LTV75%。
2. 借入100 dUSD：债务300。
3. 核对三份模拟证据：托管限制、30%储备关联、借贷池60%敞口及价格/流动性快照。
4. 发布 ORANGE 模拟断言：mUSD=$0.997，流动性100万→82万，LTV45%，停止新增借款。
5. 验证新增借款被拒绝，余额不变；即使有理论额度，也无新增借款权限。
6. 还款50：债务250。
7. 提取100 mUSD：抵押900，250债务低于900×0.997×45%=403.785，允许退出。超额提取应拒绝。
8. 将模拟时间推进至 TTL 后：原始等级仍为ORANGE，有效状态UNKNOWN，LTV保持45%，不自动恢复借款。

所有输入可重复；初始 GREEN 是显式有效断言，不是缺数据默认安全。没有真实新闻、链上状态、质押挑战或实时 AI；这些属于后续接入，不在本轮声称已实现。
